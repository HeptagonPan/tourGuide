# tourGuide 上海旅游规划工具设计说明

## 1. 项目目标

tourGuide 是一个面向中国大陆居民的本地网页旅游规划工具。第一版仅规划以上海为目的地的旅行，通过固定问答收集条件，结合真实地图数据和带来源的参考价格生成可执行的行程。

项目用于实习展示，优先保证需求完整、代码清晰、数据可追溯和本地运行简单，不追求覆盖全国或实时预订。

## 2. 硬性约束

- GitHub 仓库中受 Git 跟踪的文件总量不得超过 500MB，正常目标不超过 100MB。
- 本地完整运行环境目标不超过 1.5GB，不包含用户后续产生的导出文件。
- 后端统一使用 Python 3.12，代码遵循 PEP 8，变量和字段使用一致的英文命名。
- 公共函数、服务边界和数据模型使用明确的类型标注，统一交由 Ruff 格式化，避免手工排版产生不一致。
- 代码中的必要注释、文档字符串、界面文字和 README 使用简体中文。
- 项目使用根目录内的 `.venv`，不修改系统 Python，也不复用其他项目的虚拟环境。
- VS Code 固定使用 `${workspaceFolder}/.venv/bin/python`。
- 模型权重、虚拟环境、缓存、日志、密钥和用户导出文件不上传 GitHub。
- 每个通过验证的完整修改批次提交到 `main` 并同步 GitHub；不提交未通过测试的中间状态。

## 3. 第一版范围

### 3.1 目的地

目的地固定为上海。

### 3.2 出发城市

第一版仅支持以下预设出发城市：

1. 合肥
2. 芜湖
3. 蚌埠
4. 淮南
5. 阜阳
6. 安庆
7. 黄山
8. 马鞍山
9. 滁州
10. 南京

不接受任意城市作为大交通价格计算的输入，避免产生缺少可靠价格来源的方案。

### 3.3 不在第一版实现的内容

- 任意国内或海外目的地；
- 任意出发城市；
- 携程实时价格接口或网页抓取；
- 购买机票、火车票、酒店或门票；
- 用户账号、云同步和多人协作；
- 历史行程数据库；
- Google Maps 集成。上海市内优先使用高德官方服务，以减少访问和坐标体系问题。

## 4. 技术方案

### 4.1 主要技术

- Python 3.12；
- FastAPI：HTTP 接口和本地 Web 服务；
- Pydantic：输入、外部响应和内部数据校验；
- Jinja2：服务端 HTML 模板与独立 HTML 导出；
- 原生 CSS 和 JavaScript：问答交互和响应式界面；
- httpx：高德 Web 服务请求；
- pytest：自动化测试；
- Ruff：格式化和静态检查；
- Ollama + `qwen2.5:0.5b`：本地中文文本整理；
- 固定模板：模型不可用时的降级输出。

第一版不使用 Node.js、React 和 SQLite。

### 4.2 环境隔离

使用 `uv` 管理 Python 3.12、`.venv` 和依赖锁文件：

- `.python-version` 固定 Python 3.12；
- `pyproject.toml` 声明依赖和工具配置；
- `uv.lock` 锁定可重复安装的版本；
- `.vscode/settings.json` 指向项目虚拟环境；
- 所有安装和测试命令均从项目根目录执行。

## 5. 系统架构

```text
浏览器问答界面
      ↓
FastAPI 输入校验
      ↓
行程规划服务
  ├─ 高德客户端：地点、距离、路线、公交和天气
  ├─ 参考数据仓库：携程价格快照和来源元数据
  ├─ 大交通服务：预设城市到上海的候选路线
  ├─ 住宿服务：房间数量和住宿档位
  ├─ 预算引擎：确定性金额计算
  └─ 模型适配器：只组织已验证的数据
      ↓
交互式结果页或独立 HTML 文件
```

模型不得直接调用外部数据源，也不得自行补充地点、路线、价格和营业信息。所有金额由 Python 使用整数“分”进行计算，输出时再格式化为人民币。

## 6. 模块边界

建议目录结构：

```text
app/
  main.py                 # FastAPI 应用入口
  config.py               # 环境变量与容量约束
  api/                    # 页面与 API 路由
  schemas/                # Pydantic 输入和输出模型
  repositories/           # 本地参考数据读取与校验
  services/
    amap.py               # 高德 Web 服务适配
    transport.py          # 大交通候选方案
    accommodation.py      # 房间与住宿计算
    budget.py             # 预算计算
    planner.py            # 行程编排
    narrator.py           # 本地模型与模板降级
    exporter.py           # 独立 HTML 导出
  templates/              # Jinja2 页面
  static/                 # CSS、JavaScript 和受控图片
data/
  reference/              # 携程参考价格及来源
  presets/                # 城市、枢纽和兴趣分类
tests/
scripts/
docs/
```

每个模块只承担一个职责，并通过有类型的输入输出模型交互。

## 7. 固定问答流程

问答共七步：

1. 选择预设出发城市；
2. 填写成人、儿童人数及房间安排；
3. 选择出发和结束日期；
4. 输入人民币总预算，并确认是否包含往返大交通；
5. 多选旅行目的，包括美食文化、自然风景、城市人文、亲子活动、购物休闲和夜景摄影；
6. 选择大交通与市内交通偏好；
7. 检查右侧实时摘要并确认生成。

住宿不根据性别推断。夫妻或伴侣默认同住，其他关系默认分房，用户可以手动修改房间数和入住安排。

问答语言保持客观、直接和略微轻松，不使用夸张宣传语，也不以拟人化表达替用户作决定。

## 8. 数据来源与结构

### 8.1 高德数据

高德 Web 服务用于：

- POI 搜索和地理编码；
- 上海市内步行、公交、地铁和驾车路线；
- 距离和预计时间；
- 天气信息；
- 车站、机场和景点坐标校验。

后端使用 Web 服务密钥。若最终地图展示需要高德 JavaScript API，则使用独立的前端 Key，并在高德控制台限制使用范围。

### 8.2 携程参考数据

不抓取携程网页，不假设存在个人项目可直接使用的实时价格接口。参考数据由人工核验后写入 JSON，每条记录至少包含：

```json
{
  "id": "唯一标识",
  "category": "hotel | attraction | rail | flight",
  "origin_city": "出发城市或空值",
  "destination_city": "上海",
  "name": "产品或价格档位名称",
  "price_min_cents": 0,
  "price_max_cents": 0,
  "source_url": "来源链接",
  "observed_at": "采集日期",
  "valid_from": "适用开始日期",
  "valid_to": "适用结束日期"
}
```

完整来源保存在数据文件中。用户界面只显示“参考价格”和更新时间。

## 9. 行程生成规则

1. 校验问卷输入和支持范围；
2. 从预设数据中获取大交通候选方案；
3. 根据人数、房间数和预算选择住宿档位；
4. 根据兴趣选择上海候选 POI；
5. 使用高德验证 POI 和相邻地点路线；
6. 按区域聚类，避免同一天反复跨城；
7. 控制每日活动数量和必要休息时间；
8. 由预算引擎汇总大交通、住宿、餐饮、门票、市内交通和备用金；
9. 将经过校验的结构化结果交给本地模型润色；
10. 模型失败时使用固定模板输出同一份事实。

## 10. 结果页面

结果页采用“行程优先双栏布局”：

- 顶部：日期、人数、预算、兴趣和住宿概览；
- 主栏：按日期切换的每日时间线；
- 侧栏：当天路线地图和关键交通信息；
- 下方：大交通比较、住宿说明和预算明细；
- 操作区：返回修改、重新计算和导出独立 HTML。

视觉采用炭黑、玉绿色和少量信号红，结合经典日式编辑网格的非对称分栏、细线、留白和少量竖排标签。上海始终是内容和视觉主体，不使用日本目的地元素。

桌面端保留双栏，手机端改为单栏，并保证地图、按钮和长文本不重叠。

## 11. 异常处理

- 高德请求失败后重试一次；仍失败则明确显示无法获取，不生成替代事实；
- 本地模型不可用时自动使用模板，路线和预算功能保持可用；
- 参考价格较旧时显示更新时间提示；
- 预算不足时显示超支金额和可调整项目，不擅自删除行程；
- 日期、人数、房间数和预算不合法时阻止生成；
- 某个城市缺少有效数据时直接标记该路线暂不支持；
- 所有外部错误转换为简体中文用户提示，详细错误仅写入本地日志。

## 12. 隐私与密钥

- `.env`、缓存、日志、虚拟环境和模型文件必须在 `.gitignore` 中排除；
- 仓库只提供不含真实密钥的 `.env.example`；
- 第一版不建立用户账号，不保存问卷历史；
- 本地模型只接收本次问卷和已验证数据，不接收 API 密钥；
- 导出的 HTML 默认写入用户选择的位置，不自动上传。

## 13. 测试与验收

自动化测试覆盖：

- 日期、人数、房间和预算校验；
- 10 个出发城市的数据完整性；
- 大交通和多段接驳成本叠加；
- 高德正常、超时和错误响应；
- 预算不足与过期价格提示；
- 本地模型失败后的模板降级；
- 完整问答到 HTML 输出流程；
- 桌面和手机关键视口的布局；
- 受 Git 跟踪文件总量不超过 500MB；
- 项目虚拟环境、Ollama 运行程序和默认模型合计不超过 1.5GB。

持续集成默认使用模拟高德响应，不消耗真实配额。提供显式开启的真实接口检查，用于本地验证密钥和返回结构。

## 14. 完成标准

第一版完成时应满足：

- 用户可以从 10 个预设城市中选择出发地并完成七步问答；
- 系统可以生成上海每日行程、大交通、市内交通、住宿和预算结果；
- 每个外部事实可追溯到高德响应或本地参考数据记录；
- 模型离线时仍能生成不含虚构事实的结果；
- 可以导出独立 HTML；
- VS Code 可以直接使用项目 `.venv` 运行和调试；
- README 使用简体中文并包含安装、密钥、模型、运行和测试说明；
- 测试、格式检查和 GitHub、本地环境两项容量检查全部通过；
- 已验证的修改已经提交并同步到 GitHub `main` 分支。
