# tourGuide 上海离线数据与路线设计

## 1. 目标

将 tourGuide 的上海市内规划从运行时高德 Web 服务改为完全离线模式。项目使用本地 SQLite 数据库保存精选景点、兴趣分类、来源信息和实用级交通路线，使用户在没有高德 Key、VPN、Ollama 或外部网络时仍可完成问卷、生成行程、查看结果并导出 HTML。

本次修改保留现有七步问卷、出发城市、大交通参考价、住宿、预算、结果页和导出能力，只替换上海景点核验与市内路线的数据来源。

## 2. 范围与约束

- 目的地仍固定为上海。
- 本地数据库目标包含约 60 个精选景点，覆盖 6 类旅行兴趣和主要城区。
- 路线只达到旅游规划所需的实用级精度，不提供实时拥堵、逐路口导航、精确到分钟的到站信息或地铁出口指引。
- 结果页不保存或显示真实地图瓦片，只使用景点坐标、访问顺序和交通摘要绘制简化路线示意。
- 运行时不得调用高德或其他地图 API，也不得因缺少 API Key 而失败。
- SQLite 数据库随仓库分发并以只读方式使用；网页运行期间不修改数据库。
- Git 跟踪文件总量继续遵守 500MB 硬性上限，本地完整环境继续遵守 1.5GB 目标。
- Python 版本、FastAPI、Pydantic、Jinja2、原生 JavaScript/CSS 和现有虚拟环境保持不变。
- 后续实施每完成一个代码文件的修改即停止当前轮次，等待用户继续、Fork 或 Redo。测试文件同样视为代码文件。

## 3. 方案选择

采用 Python 标准库 `sqlite3` 与稀疏路线图，不新增数据库服务器或图计算依赖。

不采用以下方案：

- 继续使用大型 JSON：景点、兴趣、路线和来源之间的关联不易约束，后期校验成本较高。
- NetworkX 或图数据库：约 60 个景点的数据规模不需要额外运行时依赖。
- 完整 OpenStreetMap 道路数据和离线地图瓦片：容量、许可展示、路线算法和维护成本超出实习项目范围。

## 4. 系统架构

```text
七步问卷
   ↓
FastAPI 与 TripRequest 校验
   ↓
SQLite 景点仓库
   ↓
按兴趣、区域和可达性选择景点
   ↓
本地稀疏路线图计算直接路线或最短路径
   ↓
现有大交通、住宿和预算服务
   ↓
固定模板或可选 Ollama 润色
   ↓
结果页、简化路线示意和独立 HTML 导出
```

高德适配器可暂时保留为历史边界或数据维护工具，但不得进入默认规划调用链。`AMAP_WEB_KEY` 和 `AMAP_JS_KEY` 从运行要求降级为非必需配置。

## 5. 数据库设计

数据库文件固定为 `data/offline/shanghai.db`。初始化 SQL 和可审查的种子数据保存在仓库中，构建脚本以确定性方式生成数据库。

### 5.1 `pois`

保存精选景点：

- `id`：稳定英文标识，主键；
- `name`：简体中文名称；
- `district`：上海行政区；
- `area`：用于同日聚类的旅游片区；
- `longitude`、`latitude`：用于距离估算和路线示意；
- `suggested_duration_minutes`：建议游览时间；
- `admission_cents`：参考门票，单位为分；
- `opening_note`：简短开放提示，不承诺实时开放状态；
- `is_general_highlight`：兴趣不足时是否可作为通用补充景点；
- `source_id`：景点事实来源；
- `verified_at`：人工核验日期。

### 5.2 `interests` 与 `poi_interests`

`interests` 保存现有 6 个兴趣标识和中文名称。`poi_interests` 建立景点与兴趣的多对多关系，并通过外键防止无效引用。

### 5.3 `route_edges`

保存常用景点之间的双向或单向路线边：

- `origin_poi_id`、`destination_poi_id`；
- `transport_mode`：`walk`、`metro`、`bus` 或 `mixed`；
- `duration_minutes`：实用级预计时间；
- `distance_meters`：近似距离；
- `summary`：主要线路或步行建议；
- `is_bidirectional`：是否可反向复用；
- `source_id`：公开来源或人工估算说明；
- `verified_at`：核验日期。

路线图只保存合理的同片区和相邻片区连接。运行时允许经过中间景点计算最短路径，但结果页只呈现用户当天访问景点之间的汇总路线，不把中间图节点误报为游览活动。

### 5.4 `sources` 与 `metadata`

`sources` 保存来源名称、URL、许可证或使用说明、查看日期和来源类型。`metadata` 保存数据库版本、生成时间、景点数量和路线版本。

数据库启用外键、唯一约束、非负金额与时间检查，并为兴趣、区域和路线端点建立索引。

## 6. 数据来源与许可证

- 景点名称、开放提示和门票优先采用上海市文旅部门、场馆或景点官方网站。
- 坐标采用允许公开再分发的 OpenStreetMap 数据，并在 README、数据库来源表和结果来源说明中保留 ODbL 归属。
- 主要地铁线路和站点采用上海地铁公开信息。
- 路线时间和距离标记为人工整理的近似值，保存核验日期，不冒充实时导航数据。
- 不将高德 API 响应复制到公开数据库，避免违反数据再分发限制。
- 数据导入以人工核验和结构化种子文件为主，不实现持续网页抓取。

## 7. 组件边界

### 7.1 离线仓库

离线仓库负责打开只读 SQLite、检查数据库版本、加载景点、按兴趣和区域查询、读取来源。调用方只依赖有类型的 Python 模型，不直接拼接 SQL。

### 7.2 本地路线服务

路线服务从仓库加载稀疏图，优先返回直接边；没有直接边时使用标准库实现 Dijkstra 最短时间路径。服务返回交通方式、预计时间、近似距离、摘要、核验时间和来源标识。

### 7.3 行程规划器

规划器根据兴趣筛选景点，优先按片区组成每日候选集，再根据本地路线可达性排序。每天安排 2–4 个活动，并避免连续跨越距离过大的片区。现有预算、住宿和城际交通服务继续接收相同类型的数据。

### 7.4 数据构建与校验

独立脚本从仓库内的可审查种子数据生成 SQLite。构建过程可重复，输入相同则数据库结构和记录相同。校验脚本检查数量、外键、来源、兴趣覆盖、路线连通性、异常数值和容量。

## 8. 数据流

1. 用户提交问卷，由 `TripRequest` 校验。
2. 离线仓库根据兴趣取得候选景点。
3. 规划器按片区、通用程度和路线可达性选择每天 2–4 个景点。
4. 路线服务为相邻活动查询直接边或本地最短路径。
5. 景点门票与路线成本进入现有预算引擎。
6. 结构化结果交给固定模板；Ollama 可用时仅润色已有事实。
7. 结果页展示每日时间线、实用级交通文字和简化路线示意。
8. 导出器生成完全独立且不需要网络资源的 HTML。

## 9. 异常与降级

- 数据库缺失、损坏或版本不兼容：返回明确中文错误和修复提示，不尝试联网。
- 兴趣候选不足：使用同片区的通用热门景点补足，并保留推荐依据。
- 路线没有连接：优先替换为同片区可达景点；仍无法连接时减少当天活动数量，不编造路线。
- 数据陈旧：显示数据库更新时间提示，但允许继续生成。
- Ollama 不可用：使用固定模板，路线和预算保持可用。
- 高德 Key 缺失或失效：不影响任何默认功能。

## 10. API 与界面影响

- `POST /api/plans` 的请求结构保持不变，现有网页不需要更改问卷字段。
- `TripPlan` 保持现有主要字段，来源标识由 `amap-*` 改为本地数据库来源。
- 结果页移除任何实时地图暗示，路线区域明确标为“离线路线示意”和“预计用时”。
- 数据更新时间来自 SQLite `metadata` 或记录的最大核验日期。
- `/docs`、`/api/options`、`/api/export` 和 `/health` 保持兼容。

## 11. 测试与验收

- 数据库包含约 60 个景点，覆盖现有 6 类兴趣和主要城区。
- 每个景点都有来源、坐标、区域、游览时长和核验日期。
- 每条路线边都有方式、时间、距离、摘要以及来源或人工估算标识。
- 数据库约束能够拒绝无效外键、负数金额、负数时间和重复路线。
- 路线测试覆盖直接边、多边最短路径、双向边、断开图和循环图。
- 规划测试覆盖兴趣筛选、区域聚类、通用景点补足、无路线减项和 1–14 日行程。
- 测试期间阻止所有外部 HTTP 请求，完整规划仍应成功。
- `.env` 不含高德 Key时，问卷、结果页和独立 HTML 导出端到端测试通过。
- 桌面和手机结果页的简化路线示意无重叠和横向溢出。
- Git 跟踪文件继续低于 500MB，本地环境继续低于 1.5GB。

## 12. 迁移与兼容

实施顺序遵循测试驱动：先定义本地模型和仓库测试，再生成数据库，然后实现路线服务，最后替换规划器依赖和界面措辞。高德适配器及其测试在默认离线流程稳定前保留，避免一次性删除导致难以回退。

真实高德 Key 继续只保存在被忽略的 `.env`，但 README 不再要求配置。离线端到端验收通过后，可由用户决定是否彻底删除高德适配器和配置字段。

## 13. 完成标准

- 新用户无需申请任何地图 API Key 即可生成上海行程。
- 断开外部网络后，完整问卷到 HTML 导出流程仍然成功。
- 行程只使用本地数据库中有来源的景点和路线事实。
- 路线说明达到实用级规划精度，并明确不是实时导航。
- 数据可以通过确定性脚本重建和校验。
- 所有测试、Ruff、浏览器验收和容量检查通过。
- 简体中文 README、数据来源和维护方式与新架构一致。
